# Satchel bag — implementation spec

Approved design: `DESIGN.md`, mockups from `mock_bag.py` / `anim_bag.py`. Assets are generated by
`export_bag.py` (re-run it after changing any generator; it rewrites the PNG/PAL/BIN files and
`src/data/item_menu_satchel.h`). Code lives in `src/item_menu.c`, `src/item_menu_icons.c`,
`include/item_menu.h`, `include/item_menu_icons.h`, `src/graphics.c`, `include/graphics.h`.

The Battle Pyramid bag (`src/battle_pyramid_bag.c`) keeps the OLD look and still uses
`gBagScreen_Gfx` / `menu.png` / swap-line gfx — do not delete or change old assets/symbols it uses.

## Screen layout (30x20 tiles)

| Layer | Content |
|---|---|
| BG0 (text, prio 1) | item list, description, pocket name, TM/HM info windows — all transparent fill |
| BG1 (popups, prio 0) | context menu, message box, yes/no, quantity, money (unchanged) |
| BG2 (art, prio 2) | `satchel_screen.png` + `satchel_screen.bin`: wheel, header tab, 6 pill rows, scrollbar track, description tray. Index 0 = transparent |
| BG3 (grid, prio 3) | NEW. Scrolling grid. charBase 3, mapBase 28. Map filled at runtime with the 4 grid tiles (`SATCHEL_GRID_TILE_BASE` + TL,TR,BL,BR repeating 2x2) using palette `SATCHEL_PAL_GRID`. No tilemap buffer needed (write VRAM directly or use a buffer — either). Scroll diagonally down-right 1px every 4 frames (BG3HOFS/BG3VOFS decreasing so the pattern moves down-right), updated each frame from the bag's main CB/VBlank. |

BG3's map at screenblock 28 overlaps charblock 3 from tile 256 up: BG2+grid tiles must stay < 256
(currently 112 — `export_bag.py` asserts it).

BG palettes: load `satchel_screen_{male,female}.pal` (48 colours = 3 palettes) to BG_PLTT_ID(0):
0 = normal kit palette, 1 = selected (pill faces gold), 2 = grid. Gender choice same rule as now
(`!IsWallysBag() && gender != MALE` → female). Slots 12–15 unchanged (TM/HM icons, message box,
window frame, std menu).

- `gSatchelRing_Gfx` = `satchel_ring.png` (32x32), `gSatchelThumb_Gfx` = `satchel_thumb.png` (8x16) — both use the pocket-icons palette (share its palette tag)

## Windows (sDefaultBagWindows)

All bag text windows use **paletteNum 0** (kit palette) instead of 1. Text colours (`sFontColorTable`):
- `COLORID_NORMAL` = {0 transparent, 1 INK, 5 PANEL_SHADE}
- `COLORID_POCKET_NAME` = {0, 3 WHITE, 7 ACCENT_DARK}
- `COLORID_GRAY_CURSOR` = {0, 2 INK_SOFT, 5 PANEL_SHADE}
- add `COLORID_REGISTERED` = {0, 7 ACCENT_DARK, 5 PANEL_SHADE} (the "SELECT" tag)

| Window | new left,top | w x h | notes |
|---|---|---|---|
| WIN_ITEM_LIST | 13,2 | 16x12 | = the pill area. 6 rows of 16px |
| WIN_DESCRIPTION | 5,14 | 25x6 | tray right of the icon well |
| WIN_POCKET_NAME | 17,0 | 8x2 | centred in the header tab (centre x=168) |
| WIN_TMHM_INFO_ICONS | 5,14 | 5x6 | |
| WIN_TMHM_INFO | 11,14 | 4x6 | |

Recompute baseBlocks so no two coexisting windows overlap (BG0/BG1 share charblock 0; tiles may run
past 512 into charblock 1, but must stay below charblock 3 = tile 1536). Suggested:
border 1–9, msgbox 10–0x26, LIST 0x27 (192 tiles), DESCRIPTION 0xE7 (150), TMHM_INFO_ICONS 0x17D (30),
TMHM_INFO 0x19B (24), POCKET_NAME 0x1B3 (16), ITEMWIN_MESSAGE + WIN_MESSAGE 0x1C3 (108),
context/yesno/quantity windows 0x22F (max 84), MONEY 0x283 (20), QUANTITY_WIDE 0x297 (20).
Keep ITEMWIN_* positions/sizes as they are.

`MAX_ITEMS_SHOWN` 8 → `SATCHEL_LIST_ROWS` (6).

### Description text
FONT_NORMAL is 16px per line; the tray needs a **14px line pitch** starting 1px lower so text clears
the stitched seam. In `BagMenu_Print`, when `windowId == WIN_DESCRIPTION` and `fontId == FONT_NORMAL`:
`left += 2; top += 1; lineSpacing = (u8)-2;` — the text printer adds `maxLetterHeight + lineSpacing`
to the u8 `currentY`, so this wraps to +14. Add a clear comment. (Applies to item descriptions and
the "X is selected / Toss how many" prompts alike.)

## Item list

`sItemListMenu`: `item_X = 7`, `cursorKind = CURSOR_INVISIBLE` (no ▶ — the gold pill IS the cursor),
`upText_Y = 1`, `fontId FONT_NARROW` (unchanged).
- Quantity "×NN": right-aligned to x = 119 in the list window (unchanged value works: pill is 128px wide, right cap ~9px).
- Registered item: instead of blitting `sRegisteredSelect_Gfx`, print the string "SELECT" (FONT_NARROW, `COLORID_REGISTERED`) right-aligned to x = 119.
- HM rows: blit `gSatchelHMIcon_Gfx` instead of `gBagMenuHMIcon_Gfx` (same position).
- Remove the arrow-cursor drawing in normal flow. `BagMenu_PrintCursorAtPos` / `BagMenu_PrintCursor`: make them draw nothing (keep the erase path harmless). Swap mode: instead of the grey arrow on the origin row, keep the **origin row's pill gold** while swapping (see pills below); the swap line marks the destination.
- Swap line: `UpdateSwapLineSpritesPos(..., 8 | SWAP_LINE_HAS_MARGIN, 120, ...)` → x 104 (list window now starts at x=104).

### Pill rows (BG2 tilemap, `gBagMenu->tilemapBuffer`)
Write a helper `static void Satchel_DrawPills(u8 rowsVisible, u8 numRows, s8 highlightRow)`:
for r in 0..5 → tile rows `SATCHEL_LIST_TOP_TILE + 2r` and `+1`, columns `SATCHEL_PILL_COL..+SATCHEL_PILL_COLS-1`:
- r < min(rowsVisible, numRows): entry = `sSatchelPillRow[k][c] | ((r == highlightRow ? SATCHEL_PAL_SELECTED : SATCHEL_PAL_NORMAL) << 12)`
- otherwise: 0 (blank tile → grid shows)
then `ScheduleBgCopyTilemapToVram(2)`.
- `numRows` = `gBagMenu->numShownItems[pocket]`.
- `highlightRow` = visible row of the cursor (`list->selectedRow` in the move-cursor callback; `ListMenuGetScrollAndRow` elsewhere). While swapping: the visible row of `gBagMenu->toSwapPos` (or -1 if scrolled off).
- Call it from `BagMenu_MoveCursorCallback` (every move, including onInit), after list init, after swaps, and in `ReturnToItemList`/`CloseItemMessage` paths where the list is rebuilt.
- Remove `DrawItemListBgRow` / the tile-11 / tile-17 fills and `DrawPocketIndicatorSquare` BG writes (old menu.png tile indices no longer exist).

### Scrollbar (replaces the list up/down arrows)
`CreatePocketScrollArrowPair` → create a thumb sprite (`gSatchelThumb_Gfx`, 8x16, shares pocket-icon
palette tag) at x = `SATCHEL_TRACK_X`, only when `numItemStacks > numShownItems`; y = `SATCHEL_TRACK_TOP + SATCHEL_TRACK_SPAN * scroll / (numItemStacks - numShownItems)` (sprite top edge; convert to centre).
Update it whenever the scroll position changes (move-cursor callback). `BagDestroyPocketScrollArrowPair`
destroys it. Keep the existing task-id fields consistent (set to TASK_NONE / unused) so other code paths
that check them still work.

## Pocket header

- Pocket name: window as above; keep the existing slide animation (`CopyPocketNameToWindow`).
- Pocket switch arrows: replace the `AddScrollIndicatorArrowPair(&sBagScrollArrowsTemplate…)` pair with
  two small sprites (`gSatchelArrow_Gfx`, own palette tag) at (`SATCHEL_ARROW_LEFT_X`, `SATCHEL_ARROW_Y`)
  and (`SATCHEL_ARROW_RIGHT_X`, same y, hFlip). Give them a gentle Gen 3 bounce: x2 oscillates 0→-2→0
  (left) / 0→+2→0 (right) over ~32 frames. Respect `pocketSwitchDisabled` (don't create them then),
  and every create/destroy site of the old pair (incl. `StartItemSwap`, `ReturnToItemList`, Wally tutorial).

## Wheel sprites (item_menu_icons.c)

- **Satchel**: replace bag sprite sheet/palette with `gSatchel{Male,Female}_Gfx/_Pal` (gender-selected
  palette, same tag `TAG_BAG_GFX`). Position: centre (`SATCHEL_WHEEL_X`, `SATCHEL_WHEEL_Y`).
  Frame mapping (tile offsets, 64 tiles per frame): closed = 0, POCKET_ITEMS = 64, POKE_BALLS = 128,
  TM_HM = 192, BERRIES = 256, KEY_ITEMS = 320 (`sBagSpriteAnimTable`).
  Keep the existing switching behaviour (closed frame, y2 = -5 rising 1px/frame, then pocket frame) and
  the affine shake (`ShakeBagSprite`) — call `ShakeBagSprite()` at the start of every pocket switch too.
- **Pocket buttons**: 5 sprites (32x32, `gSatchelPocketIcons_Gfx`, 10 single-frame anims) at
  `sSatchelButtonPos[k]`, priority above the satchel. Anim = k (normal) or k+5 (selected). On open, the
  current pocket is selected.
- **Travelling ring** (pocket switch): on each switch, all buttons go to normal; spawn/retarget one
  ring sprite (`gSatchelRing_Gfx`) that moves along the wheel from the current angle to
  `sSatchelButtonAngle[newPocket]` going the direction of the press (R / right = +, i.e. clockwise =
  increasing angle; L / left = −), over 12 frames with ease-out: `angle = from + delta * t * (24 - t) / 144`.
  Position = wheel centre + `SATCHEL_BUTTON_RADIUS` * (Cos2(angle), Sin2(angle)) / 4096 (`Sin2`/`Cos2`
  take degrees). On arrival: destroy the ring, set the new button to its selected anim. A press while
  travelling retargets from the ring's current angle (delta = shortest step in the press direction).
  `IsVictoryCatch()` skips Poké Balls — the ring must then travel two steps.
- **Rotating ball** (`AddSwitchPocketRotatingBallSprite`): no longer used — make it a no-op.
- **Item icon**: centre at (`SATCHEL_ICON_X`, `SATCHEL_ICON_Y`) (x2/y2 in `AddBagItemIconSprite`).
- Allocate/free all new tags in the existing `RemoveBagSprite` / exit paths so nothing leaks between opens.

## Pocket switch list wipe

`SwitchBagPocket`: clear the list text window, `Satchel_DrawPills(0, …)` (all rows blank).
`Task_SwitchBagPocket` state 0 (16 frames): `Satchel_DrawPills(timer * SATCHEL_LIST_ROWS / 16 + 1, numShownItems[newPocket], 0)`
so rows wipe in top to bottom; state 1 rebuilds the list and draws pills with the real highlight.

## Window frame in the bag

Replace `LoadUserWindowBorderGfx(0, 1, BG_PLTT_ID(14))` with loading the Orchid frame
(`gTextWindowFrameOrchid_Gfx` 9 tiles → BG0/1 tile 1, `_Pal` → BG_PLTT_ID(14)) via `LoadBgTiles` /
`LoadPalette`. Everything that calls `DrawStdFrameWithCustomTileAndPalette(…, 1, 14)` then shows it.
(Context menus/yes-no keep the ▶ cursor for now — pill cursors in std windows are the next phase.)

## Graphics loading (`LoadBagMenu_Graphics`)
- state 0: `gSatchelScreen_Gfx` → BG2 charblock (DecompressAndCopyTileDataToVram(2, …)).
- state 1: decompress `gSatchelScreen_Tilemap` → `gBagMenu->tilemapBuffer`; then fill BG3 map.
- state 2: load the 3 BG palettes.
- state 3/4: satchel sheet + gender palette; pocket icons sheet + palette; ring, thumb, arrow sheets.
`BagMenu_InitBGs`: add the BG3 template, `ShowBg(3)`, reset BG3 scroll. Make sure BG3 is hidden/reset on exit like the others.

## Don't break
All `ITEMMENULOCATION_*` contexts, Wally's tutorial (scripted right switch + context menu), sell/deposit
flows, berry-tree contexts (`pocketSwitchDisabled`), TM/HM info windows, item swap, registered items,
`item_use.c` callers of `DisplayItemMessage`/`CloseItemMessage`/`BagMenu_YesNo`, `berry_tag_screen.c`
return path, and the Battle Pyramid bag.

## Implementation notes / deviations

- Pills are redrawn only from `BagMenu_MoveCursorCallback`. `ListMenuInit` always calls it (onInit),
  so every list rebuild (setup, swaps, toss/sell/deposit, `CloseItemMessage`, sort, register) is covered
  without extra calls. The thumb position is updated there too.
- Pocket-switch wipe highlights `gBagPosition.cursorPosition[newPocket]` instead of row 0, so the gold
  pill doesn't jump from row 0 to the real row when state 1 rebuilds the list.
- `ShakeBagSprite` and the pocket-switch rise both own `sprite->callback`. The rise callback now hands
  over to `SpriteCB_ShakeBagSprite` when it finishes (resetting the affine anim), and `ShakeBagSprite`
  doesn't replace the rise callback.
- Ring, thumb and arrow sheets are uncompressed (`.4bpp`, `LoadSpriteSheet`). The pocket icons and
  satchel sheets are `.smol`. All of the satchel sprite code (buttons, ring, thumb, arrows) lives in
  `item_menu_icons.c` behind a small API in `item_menu_icons.h`. Sprite ids are kept in new
  `ITEMMENUSPRITE_*` slots, and `pocketScrollArrowsTask` / `pocketSwitchArrowsTask` stay `TASK_NONE`.
- `gBagMaleSpriteSheet`/`gBagFemaleSpriteSheet` now point at the satchel sheets.
  `gBagPaletteTable` is split into `gBagMalePaletteTable`/`gBagFemalePaletteTable`. The old
  `gBagMaleTiles`/`gBagPalette` symbols are still defined but no longer used.
- The rotating-ball data and callbacks are deleted. `AddSwitchPocketRotatingBallSprite` is an empty
  no-op. `BagMenu_PrintCursorAtPos` is removed, and `BagMenu_PrintCursor` is an empty no-op.
- The BG3 map is written straight to VRAM (`Satchel_FillGridMap`) after the BG2 tile DMA finishes.
  BG3 is not hidden explicitly on exit, the same as BG0–2. The next screen's BG/VRAM reset clears it.
